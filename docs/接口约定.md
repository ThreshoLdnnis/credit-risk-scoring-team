## 数据与目标

官方来源：https://www.kaggle.com/competitions/GiveMeSomeCredit/data 。使用有标签的 `cs-training.csv` 建模。`SeriousDlqin2yrs=1` 表示两年内发生 90 天或以上严重逾期事件，0 表示未发生；这不是预期信用损失标签。官方 `cs-test.csv` 缺少真实标签，只能预测，不能据此计算真实 AUC。

输入字段按以下顺序固定，CSV 导出序号和标签不入模：

```text
RevolvingUtilizationOfUnsecuredLines
age
NumberOfTime30-59DaysPastDueNotWorse
DebtRatio
MonthlyIncome
NumberOfOpenCreditLinesAndLoans
NumberOfTimes90DaysLate
NumberRealEstateLoansOrLines
NumberOfTime60-89DaysPastDueNotWorse
NumberOfDependents
```

`load_dataset` 保留原始行顺序，检查必需列、重复列、非数值与无限值、有标签模式下的有效二元标签；不把非法文本直接当成正常缺失。无标签模式不要求 y，也不能进入效果评价。

## 清洗与分区

`clean_features` 返回新表：排除标签、序号和其他未约定字段；age=0 设为缺失；三个逾期次数字段中的 96/98 添加各自 `__special` 指示列，再将原值设为缺失。上述是事先约定的研究处理，不将其宣称为官方业务定义。其他数值不随意截断、删行。缺失保留到各模型的训练内处理阶段。

将清洗后 13 个输入列作为内容组依据，缺失值以一致方式参与组定义。相同输入绑定同组，不直接删掉重复行；组内可能有不同标签，组最大标签仅用于分层，原 y 逐行保留。按组目标 70/15/15、seed=42 切分，返回 `train`、`validation`、`test` 的原始行位置。各区有两类、全行恰好覆盖一次、组交集为空。按组划分的行数比例可有小偏差。

后续 `train_x = features.iloc[positions['train']]`，对应 y 必须取同一行位置。所有模型复用同一份分区成员；保存原始行标识、内容组指纹和文件 SHA256 作为本地证据。

## 模型接口

训练函数返回 `bundle`：由实现者选择字典或类，但要在代码注释和 README 说明保存的模型、变换、字段顺序、参数与版本。预测不重新 fit。所有概率向量按输入行顺序返回，表示 y=1。

| 模块 | 训练输入 | 预测输出 |
| --- | --- | --- |
| 简单 LR | train_x、train_y、settings | 正类概率；训练内中位数填补/缺失指示、标准化、L2 LR |
| 评分卡 | train_x、train_y、settings | DataFrame：probability、score、base_points、各 points_列 |
| LightGBM | train_x/y、validation_x/y、settings | 正类概率；验证集早停，保存有效轮数与预处理 |

评分卡先对训练数据监督分箱及 WOE/IV，按 IV 规则选变量，再训练 LR。使用 OptBinning 原生 WOE/IV，记录逐箱好坏计数、边界、求解状态与缺失策略；常规求解须为 OPTIMAL 或 FEASIBLE。未观测缺失、常量、全缺失等情况要事先定义可复现的处理，不能静默吞掉求解失败。六项练习的 alpha 平滑公式仅用于教学核对，不冒充 OptBinning 的默认统计定义。

评分尺度：BaseScore=600、BaseOdds=20（好:坏）、PDO=20；Factor=PDO/ln(2)，Offset=600-Factor*ln(20)，Score=Offset-Factor*logit(p)。`base_points=Offset-Factor*intercept`，各特征分项为 `-Factor*coefficient*WOE`。以浮点未取整值验证加和；非法概率不静默改写，数值饱和时明确处理策略并记录。

## 评价与解释

`select_threshold` 只接收验证集，用最大 TPR-FPR 的有限 [0,1] 阈值；并列取较大值。它是研究演示规则，不是实际审批策略。配置、模型选择与阈值固定后才报告测试分区结果，不反复用测试成绩调参。

`evaluate_binary` 返回 AUC、KS=max(TPR-FPR)、AP、梯形 PR 面积、Brier、Log loss、阈值、TN/FP/FN/TP、Precision/Recall/F1，声明 p>=threshold。AP 与梯形 PR 面积使用不同名称。测试各模型样本相同、标签对齐。曲线至少含 ROC、PR、校准和信用分分布，图注写明模型、分区与样本数。

`explain_tree` 解释原始 log-odds：base + sum(SHAP) 等于 raw_score，sigmoid(raw_score) 等于正类概率。记录解释器模式、背景数据来源、解释样本选择与完整特征顺序。背景选自训练数据；展示局部贡献时计入省略项，不把 log-odds 贡献写成概率百分点或因果效应。

## 保存与页面

`run_pipeline.py` 已支持简单 LR、评分卡与 LightGBM：CLI 使用 `--models baseline scorecard tree` 同时运行，或用 `--models tree` 等参数选择子集；省略参数时保留原有简单 LR 行为。公共 API 原有三参数不变，新增可选关键字 `models`。入口给简单 LR 传完整配置，给评分卡明确传 `settings["scorecard"]`；给树模型传完整配置、训练集及验证集，后者只用于 AUC 早停。树模型保存 `best_iteration`、`evaluation_rounds` 与 `validation_auc_history`，预测显式使用最佳轮数。全部模型共享清洗结果和分区，各自的验证阈值统一保存后才开始测试预测。入口的旧 `metrics`、`validation_threshold` 函数保留名称，统一委托 `src/evaluation.py`。每个实验使用唯一输出目录，保存配置、数据/代码版本、环境、分区证据、模型、逐箱表、指标、曲线与日志。原始数据、模型和逐行预测留本地，仓库报告只记录可共享的汇总与说明。

共享入口的 `record["models"]` 和 `model_metrics.json` 保存所有选定模型结果，`model_comparison.csv` 按模型/分区汇总。`model/metrics/preprocessing` 旧字段保留首个模型的兼容视图（同时运行时是 baseline）。评分卡另存 `scorecard_binning.json`、`scorecard_predictions.csv`，包含原生分箱证据及逐行概率、信用分、基准分、各分项；后者留在本地。`selection.json` 是首个模型的兼容视图，`selections.json` 记录全部模型。`tree.joblib` 和 `tree_predictions.csv` 是树模型本地产物；`record["models"]["tree"]` 记录最佳轮数及验证历史。曲线按 validation/test 分目录保存到 `figures/`，记录中的 `figures` 提供相对路径，`output_sha256` 递归覆盖曲线和其他产物。没有评分卡时不生成信用分图。接入步骤见 [共享入口接入](共享入口接入.md)。

`app.py` 在 Day 5 接入团队实际训练产物，实现模型比较、手工输入、概率与评分、SHAP 展示。先校验输入；无模型或无指标时明确提示。使用与离线相同的预处理和推理对象，检查同输入得到相同结果。当前模板页面只有 TODO。
