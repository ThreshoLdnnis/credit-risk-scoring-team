## 开工与提交

1. 打开上表对应 Issue，核对署名、允许修改的路径和接口。新增任务另建 Issue，并写明主责。
2. 从最新 main 建任务分支；跨模块任务分别确认各人的子项与文件，同一文件不安排两人同时主改。
3. PR 关联 Issue，展示本人验证；同伴审查、负责人确认合并后关闭任务并更新进度。

## 共享文件的修改顺序

`run_pipeline.py`、`configs/experiment.json`、依赖、CI 和根目录 README 由项目负责人（ThreshoLdnnis）协调。三位成员通过 Issue/PR 提出具体修改。最终报告由负责人整合：数据部分吴晓亦，评分卡与界面部分杨曦，模型、评价和解释部分郭宇哲。
