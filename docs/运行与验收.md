# 完整运行、复现与验收

## 1. 环境与数据

使用 Python 3.11，在仓库根目录建立环境。Windows 示例：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe check_environment.py
```

已有 uv 的成员也可用 `uv venv --python 3.11 .venv`，再运行 `uv pip install --python .venv/Scripts/python.exe -r requirements.txt`。macOS/Linux 的解释器路径换成 `.venv/bin/python`。依赖版本由 `constraints.txt` 约束。

真实数据放 `data/raw/cs-training.csv`，或在运行时用 `--input` 指定其他本地路径。指定文件 SHA256：

```text
1bd46da486a5708c58c7b01a034fae2a13b327f6f7b62ea7ba4fe3b5824b24ac
```

没有该文件时先按 Kaggle 规则取得数据；不得以人工数据或无标签 `cs-test.csv` 冒充真实效果实验。

## 2. 一条命令跑完整工程

```powershell
.venv\Scripts\python.exe run_project.py --output artifacts/team/run-001
```

该入口固定运行三模型，复用已有配置与分区，不改变模型参数。依次完成依赖导入、模型管线、吴晓亦的独立数据审计、郭宇哲的模型重载/解释核验及页面产物关联检查。`delivery.json` 只在全部技术步骤完成后标记成功；异常时保留失败步骤。解释样本默认为固定 seed=42 的 1000 条测试分区记录，可用 `--sample-size` 指定数量。

```text
artifacts/team/run-001/
├── delivery.json              完整技术交付记录及代码/产物指纹
├── environment.json           本机环境检查
├── data_audit.json            独立清洗、分区和行对应核对
└── models/
    ├── baseline.joblib / scorecard.joblib / tree.joblib
    ├── record.json / model_metrics.json / model_comparison.csv
    ├── split_positions.npz / split_members.csv
    ├── figures/               ROC、PR、校准与信用分分布
    └── explanations/          全局汇总、局部图与解释复验记录
```

这些产物均留本地。目录已有内容时使用新名称；不要覆盖一次旧实验来制造一致结果。

仅研究某个模型时，原来的 `run_pipeline.py --models ...` 继续可用。只运行模型管线不会自动生成页面全局解释；完整交付请用 `run_project.py`。

## 3. 打开页面

```powershell
.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503
```

打开 `http://127.0.0.1:8503`，依次选择实验、模型、评价分区。页面可切换三模型指标，评分卡显示信用分与分项，LightGBM 显示同一实验的全局解释和客户单笔解释。

默认扫描本仓库 `artifacts/`。如产物在其他本地目录：

```powershell
.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503 -- --artifacts-root C:/my-local-artifacts
```

十个输入框留空代表缺失；年龄0及逾期96/98使用同一套研究清洗规则。非法文本、无穷或 NaN 文本会被拒绝。只加载本人确认来源的本地模型产物。

## 4. 复验状态怎么读

- `completed_team_technical_delivery`：完整工程技术步骤已完成，不代替成员现场讲解。
- `completed_audit_with_reloaded_numeric_differences`：历史保存概率可以重算原指标，重载概率在既定容差内，但部分排序指标有差异；详情在 `models/explanations/summary.json`，不能写成所有重载指标完全相同。
- `failed`：查看 `delivery.json` 的 `failed_step` 和错误，排除后用新输出目录重跑。

原始保存概率、冻结阈值与历史记录不会被修改；源码或产物哈希不符、实际概率漂移、历史指标错误仍会中断。
