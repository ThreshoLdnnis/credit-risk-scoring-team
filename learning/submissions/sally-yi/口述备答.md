## 为什么只固定种子还不够

**口述：种子固定抽签过程，不能固定数据和名单。要同源、同规则、同版本，还要逐项核对成员。**

1. **同一原始文件：** 对解压后的 `cs-training.csv` 核对 SHA256，不只比较文件名、大小或ZIP名字。本项目为 `1bd46da486a5708c58c7b01a034fae2a13b327f6f7b62ea7ba4fe3b5824b24ac`。
2. **同一处理：** 固定代码提交、依赖版本、配置、清洗规则和行序。先按全部13个清洗特征分内容组，缺失比较一致；组最大标签只辅助分层；两次切分都用seed=42。
3. **同一测试成员：** 保存原始行位置、原序号、内容组指纹和分区名称；逐项比较位置数组与成员清单，不能只看104974／22518／22508三个数。
4. **分区和标签正确：** 所有位置合并后恰好为0至149999，每行一次；三个分区的内容组交集为空；特征和标签用同一`.iloc[positions]`取行。
5. **独立复跑：** 另一位成员用同版文件、代码和环境运行共享入口及审计脚本，比较实际输出，不能只说“脚本放在GitHub了”。

如果不便交换成员表，可比较规范化的位置数组摘要。本项目T07测试分区摘要是 `006d06c45a990dc22a0d4b876823ecba06f0fe21e70f7865c8e32951a1d238ad`，算法为：按原行位置顺序，将数组转为小端int64连续字节后计算SHA256。这个摘要用于比对，不需要背；现场重点说清“比文件和成员，而非只比种子与行数”。

原始数据留在成员本地，GitHub保存代码、配置和可共享的核对证据。

## E01 missing_rate

**背：缺失数÷总行数，0不算缺失。**

- 为什么空表报错？没有样本时分母为0，不能定义这个缺失比例。
- 为什么`df.sum()`不对？它在加原始数值。先用`df.isna()`得到是否缺失的布尔表，再按列求和或平均。
- 为什么0.5等于50%？比例乘100后加百分号；0.5不是缺失0.5条记录。
- 自己的三行例子是什么？`[1, NaN, 2]`缺1个，得1/3；`[NaN, 0, NaN]`缺2个，得2/3。
- 为什么浮点用近似比较？1/3不能被有限二进制精确表示，不能要求显示的小数永远逐位相等。

## E02 split_three_way

**背：先绑组、再分组、返回原行位置。**

- 为什么只检查行位置没有交集还不够？两条不同位置可能有完全相同输入，逐行随机分就可能把同内容放进训练和测试，造成泄漏。
- 为什么按组最大标签分层？组要作为整体抽取；最大值表达该组是否出现过标签1，仅作分层依据，原始每行y仍保留。
- 70/15/15怎么分？先把组分为70%训练和30%留出，再把留出组等分成验证、测试；两个步骤都用同一seed。
- 为什么返回位置而不返回索引标签？位置可用`.iloc`让X与y同时取同一行；DataFrame索引可能不连续或有重复。
- 新增同组记录放哪？沿用已固定的“组→分区”映射，跟随原组。若重新对变更后的数据全量切分，即便种子相同，旧成员也不保证不变，必须作为新版本记录。
- 组最大标签全是1就一定不能切吗？不一定。若每个组都同时有0/1，组层面虽只有1，切出的每区仍可同时有两类；最后检查逐行类别是否齐全。
- 训练、验证、测试各干什么？训练拟合参数，验证选择方案和阈值，测试在固定后评价。不能根据测试成绩反复调参。

## E03 roc_auc_manual

**背：正负配对，赢1分，平0.5分，输0分。**

用`y=[0,0,1,1]`、`p=[.1,.4,.35,.8]`手算：

| 正样本分数 | 对负0.10 | 对负0.40 |
| --- | ---: | ---: |
| 0.35 | 1 | 0 |
| 0.80 | 1 | 1 |

总得分3，正负配对数2×2=4，AUC=3/4=0.75。

- AUC为什么不是准确率？AUC看两类排序，不用分类阈值；准确率要先判0/1。此例阈值0.4时准确率为0.5，AUC仍0.75。
- 全同分、全排对、全排反呢？分别为0.5、1、0。
- 概率方向反过来呢？用`1-p`会反转排序，此例AUC变0.25；必须确认高概率表示标签1。
- 保持排序的变换会怎样？严格单调递增且没有改变并列关系时，AUC不变；本题概率输入仍须在[0,1]。
- 为什么只排标签不行？会破坏每个标签和对应概率的配对。重排必须同时移动y和p。
- 为什么单类标签报错？没有正负配对，分母为0；不能随便返回0.5。
- 为什么真实大数据不用这个实现？两两比较需要约“正样本数×负样本数”次比较，只适合课堂小样本；真实评价用成熟库。

## E04 woe_iv_from_counts

**背：好坏各算占比，WOE取对数比，IV把差异乘WOE再求和。**

good对应y=0，bad对应y=1；K是箱数，G和B分别是全部箱的好、坏样本总数。

```text
pg_i = (G_i + alpha) / (G + alpha*K)
pb_i = (B_i + alpha) / (B + alpha*K)
WOE_i = ln(pg_i / pb_i)
IV = sum((pg_i-pb_i) * WOE_i)
```

good=[8,2]、bad=[2,8]、alpha=0.5时，G=B=10，K=2。pg=[8.5/11,2.5/11]，pb反过来；WOE=[ln3.4,-ln3.4]约为[1.2238,-1.2238]，IV=(12/11)ln3.4约1.335028。

- 为什么分母用全体好样本或全体坏样本？比较的是“这一箱占全部好样本多少”和“占全部坏样本多少”，不是本箱坏样本率。
- 为什么分母也加alpha*K？每箱都加了alpha，共K箱；这样每类占比之和仍为1。
- 平滑为什么有用？避免零频直接造成除零或ln(0)；两类原始总数仍须大于0。
- WOE为正是什么意思？这一箱在好样本中的占比高于它在坏样本中的占比，不能简单说绝对好人数一定更多。
- 交换好坏会怎样？WOE变号，IV不变，因为占比差也同时变号。
- IV高就一定好吗？还要查标签泄漏、样本太少、分箱过拟合和不同时间样本的稳定性。
- 课堂公式和正式评分卡一样吗？课堂用题目规定的alpha平滑；正式代码用OptBinning原生统计约定，要分别说明，不能混用期望值。
- 为什么代码出现logaddexp？它等价计算平滑后的对数占比，用于避免很大但有限的计数相加溢出；需要背的是上面的统计定义。

## E05 probability_to_score

**背：风险升，分数降；好坏比翻倍，加PDO。**

这里p是严重逾期概率，好坏比O=(1-p)/p。Factor=PDO/ln2；由“基准好坏比对应基准分”推出Offset=BaseScore-Factor×ln(BaseOdds)。

```text
Score = Offset + Factor*ln((1-p)/p)
```

基准600分、好坏比20:1、PDO=20时：p=1/21→600；p=1/41→620；p=1/11→580。

- 为什么风险越高分越低？p升高使好坏比下降，对数好坏比也下降，所以分数下降。
- 600分对应多少概率？20:1意味着21份中坏样本1份，p=1/21，约4.76%。
- 自选一个翻倍例子？p=.2时好坏比为4；翻倍到8后p=1/9。若自选PDO=30，则增加30分。
- 改PDO会改变AUC吗？不会改变原概率的AUC。正PDO只改变分数尺度，未取整时保留评分排序；评价严重逾期需用风险方向，例如负信用分，不能把高安全分当成高风险。
- 为什么不接收p=0或1？log赔率在边界发散；本题规定报错，不悄悄截断。
- 为什么不提前取整？取整会损失精度并制造并列；核对PDO关系和分项加和应先用未取整值。

## E06 compare_models

**背：同样本、同标签；AUC看排序，Brier看误差，分类看阈值。**

```text
Brier = mean((p-y)^2)          # 越小越好
预测为1的条件：p >= threshold # 包含等号
```

| 真实标签＼预测 | 预测0 | 预测1 |
| --- | --- | --- |
| 真实0 | TN | FP |
| 真实1 | FN | TP |

记法：T/F说判断对错，P/N说预测正负；也可以直接背“TN真0判0、FP真0判1、FN真1判0、TP真1判1”。

| 模型与固定阈值 | AUC | Brier | TN／FP／FN／TP |
| --- | ---: | ---: | --- |
| 甲：p=[.1,.4,.35,.8]，阈值.4 | .75 | .158125 | 1／1／1／1 |
| 乙：p=[.15,.25,.55,.75]，阈值.5 | 1 | .0875 | 2／0／0／2 |

甲的Brier手算为(.01+.16+.4225+.04)/4=.158125。

- 单改阈值有什么变化？AUC和Brier不变，因为p没变；混淆矩阵会变。甲阈值从.4改.5后，TN/FP/FN/TP变为2/0/1/1。
- 阈值从哪里来？验证集预先选定，再传入函数；不能在测试集上搜索最佳阈值。
- 等长就能证明对齐吗？不能。数组接口无法凭长度判断是否属于同一人，调用方必须按同一行号取值、保存身份或内容证据；Series还能核对索引顺序。
- 小例子能证明模型乙适用于真实贷款吗？不能，只有四条人工数据，只能核对计算；真实效果还需同样本口径的研究评价及独立时间/客户数据验证。

## 现场小改可以练什么

把一题的小输入改一个数，先预测结果再运行：缺失列多放一个NaN；AUC把两分数改成相等；把PDO从20改30；只改变模型甲阈值。四次变化都能解释原因，比只背函数名更有用。
